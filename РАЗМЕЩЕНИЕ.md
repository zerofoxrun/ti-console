# Карта размещения файлов

Что где лежит: в GitLab, на машине аналитика, на сервере (когда появится),
и что не должно лежать нигде.

Это карта, а не инструкция по установке — порядок действий в `LOCAL.md`.

---

## Коротко: три разных места

| Место | Что там | Кто кладёт |
|---|---|---|
| **GitLab** | Исходники, из которых собирается всё остальное | SOC, через мерж-реквесты |
| **Машина аналитика** | Два XPI и `policies.json` | SOC или сам аналитик, по инструкции |
| **Сервер** | Пока ничего — сервера нет | — |

Ключевое правило: **на машину аналитика попадают только собранные
артефакты**, исходники туда не кладутся. Никогда не раскладывайте
на АРМ содержимое репозитория — там лежат тесты, генераторы и
аннотированные политики с комментариями, которые Firefox покажет
как ошибки.

---

## 1. GitLab

### Где создавать

Отдельный проект, не подпроект существующего. Причина: у него своя
периодичность релизов, свои теги и свой CI, а `.gitlab-ci.yml`
из соседнего проекта сюда не подойдёт.

Рекомендация по имени — `soc-tools/ti-console`. Группа `soc-tools`
пригодится: рядом со временем лягут другие внутренние инструменты.

**Видимость: Private.** В репозитории нет секретов (они в переменных
CI), но есть карта того, какие внутренние зоны блокируются политикой,
и полный разбор того, чем защищён TLP-гейт. Это не для публичного
доступа.

### Чего в репозитории нет и быть не должно

| Что | Почему |
|---|---|
| `dist/` | Артефакты сборки. Собираются из исходников; в истории они дают лишние мегабайты на каждый релиз |
| `.env` | Секреты. Шаблон — `.env.example` |
| `*.key`, `*.pem`, `*.crt` | Ключи и сертификаты |
| `policies/policies-local-linux.json` | Генерируется по требованию: `make-local.py --linux` |
| `__pycache__/`, `.pytest_cache/`, `node_modules/` | Мусор сборки |

Всё перечисленное уже в `.gitignore`.

### Почему сгенерированные политики всё-таки коммитятся

`policies-local.json` и `policies-server.json` — производные от
`policies.json`, и по общему правилу производные не коммитят.

Здесь исключение сделано осознанно: **это те самые файлы, которые
кладутся на машины**, и их должно быть видно в диффе мерж-реквеста.
Ревьюер должен видеть, что именно поедет на АРМ, а не доверять тому,
что генератор отработает правильно.

CI проверяет, что закоммиченный файл совпадает с выводом генератора.
Расхождение — красный пайплайн с указанием, что запустить.

### Переменные CI

Settings → CI/CD → Variables, все **Protected**:

| Переменная | Тип | Зачем |
|---|---|---|
| `TI_API_URL` | обычная | Адрес бэкенда, когда появится |
| `TI_SEARX_URL` | обычная | Адрес SearXNG |
| `TI_DIST_HOST` | обычная | Хост раздачи XPI |
| `TI_DIST_SSH_KEY` | **Masked** | Ключ для выкладки |
| `TI_VT_KEY` | **Masked** | Ключ VirusTotal для серверного обогащения |
| `TI_PG_PASSWORD` | **Masked** | Пароль PostgreSQL |

Пока сервера нет, нужны только первые — и то не все. Заводите по мере
появления, а не заранее: пустая Masked-переменная маскирует пустую
строку и ломает логи.

### Ветки и теги — то, на чём держится откат

| Что | Правило |
|---|---|
| `main` | Защищённая. Только через мерж-реквест, прямой push запрещён |
| `feature/*` | Рабочие ветки |
| Теги `vX.Y.Z` | Ставятся на `main` после зелёного пайплайна |

**Откат — это возврат к тегу, а не правка на месте.** Каждая версия,
уехавшая на АРМ, обязана иметь тег: без него «вернуть как было»
превращается в археологию.

Settings → Repository → Protected branches: `main`, Allowed to push —
**No one**, Allowed to merge — Maintainers.
Protected tags: `v*`, Allowed to create — Maintainers.

## 2. Машина аналитика

### Windows

```
C:\TI-Console\
    ti-console.xpi                  <- из архива, имя БЕЗ версии
    ti-console-theme.xpi            <- из архива, имя БЕЗ версии

C:\Program Files\Mozilla Firefox\
    distribution\policies.json      <- policies.json из архива
```

Если расширение не подписано (вариант A из `LOCAL.md`), ещё два файла:

```
C:\Program Files\Mozilla Firefox\
    defaults\pref\autoconfig.js
    firefox.cfg
```

**Почему не `Program Files` для XPI.** Раньше они лежали там, и это
давало `ERROR_NETWORK_FAILURE` без внятной причины: Windows
перенаправляет неэлевированную запись в `Program Files` в VirtualStore,
и Проводник показывает файл, которого по пути нет. `C:\TI-Console\`
выбран именно поэтому — не из вкуса.

**Имена без версии обязательны.** Политика ссылается на
`file:///C:/TI-Console/ti-console.xpi`. Файл с версией в имени
политика не найдёт, и расширение молча не поставится.

### Linux

```
/opt/ti-console/ti-console.xpi
/opt/ti-console/ti-console-theme.xpi
/etc/firefox/policies/policies.json      <- linux/policies.json из архива
```

Для варианта A: `/usr/lib/firefox/defaults/pref/autoconfig.js`
и `/usr/lib/firefox/firefox.cfg` — путь зависит от дистрибутива.

### Что на машину аналитика НЕ кладётся

| Что | Почему |
|---|---|
| Исходники расширения | На АРМ нужен собранный XPI, а не папка с кодом |
| `policies/policies.json` (аннотированный) | Комментарии Firefox покажет как **Unknown policy** в `about:policies` → Errors. Кладётся только сгенерированный |
| `backend/`, `docker-compose*.yml` | Это сервер |
| Тесты, `tools_*.py` | Кроме `check-install.ps1` для диагностики и `tools_check_links.py`, если хотите проверять реестр с этой машины |

### Что создаётся само и живёт только там

| Что | Где | Важно |
|---|---|---|
| Кейс с индикаторами | Профиль браузера, `browser.storage.local` | **Сброс профиля уничтожает кейс.** Выгружайте в файл |
| Разрешение `<all_urls>` | Профиль | Выдаётся аналитиком при первом заборе страницы по ссылке |
| Настройки FoxyProxy | Профиль FoxyProxy | Заводятся руками, политикой не раздаются |

## 3. Сервер

Сейчас его нет, и всё работает без него. Когда появится:

```
/opt/ti-console/
├── docker-compose.yml           из репозитория
├── docker-compose.small.yml     профиль для слабой ВМ
├── .env                         ИЗ .env.example, заполняется на месте
├── backend/                     собирается в образ, не копируется файлами
└── searxng/settings.yml
```

`.env` создаётся **на сервере** копированием `.env.example` и правится
руками. В репозиторий он не возвращается никогда.

Раздача XPI — отдельный каталог веб-сервера, и вот там имена
**с версией**: `ti-console-0.16.0.xpi`. Политика в серверном варианте
ссылается на `ti-console-latest.xpi` — симлинк на текущую версию.
Разница с локальным вариантом намеренная: на сервере нужна история
версий для отката, на АРМ — предсказуемое имя для политики.

Порядок развёртывания — `RUNBOOK.md`.

## 4. Ключ провайдера модели — когда вернётесь к нейросети

Работа приостановлена, но вопрос «куда класть ключ» решается заранее,
потому что ответ меняет конфигурацию.

| Конфигурация | Где ключ | Чем плохо |
|---|---|---|
| **Без сервера** (сейчас) | `policies.json`, ключ `llmApiKey`, на каждой машине | Ключ читает и аналитик через `about:debugging`, и любой код в контексте расширения. Считайте его известным всем, у кого есть доступ к машине |
| **С сервером** | `.env` на сервере, наружу не выходит | Требует сервера |

Если идёте без сервера — **единственная работающая защита это жёсткий
лимит трат на стороне провайдера**. Не «следить за счётом», а именно
ограничение, после которого ключ перестаёт работать.

Ключ в репозиторий не коммитится ни в каком варианте: в `policies.json`
он остаётся пустой строкой, а подставляется при сборке политики
из переменной CI.

## 5. Порядок первого заведения в GitLab

```bash
# 1. Создать пустой проект soc-tools/ti-console в GitLab (Private)

# 2. Локально
cd ti-console
git init
git add -A
git commit -m "init: TI Console 0.16.1"
git remote add origin git@gitlab.internal:soc-tools/ti-console.git
git push -u origin main
git tag -a v0.16.1 -m "Первая версия в GitLab"
git push origin v0.16.1

# 3. Защитить main и теги (Settings -> Repository)
# 4. Завести переменные CI по мере надобности
```

После первого push пайплайн прогонит 185 браузерных тестов,
48 серверных и проверку конфигурации. Если что-то красное — чинится
код, а не тест: проверки написаны так, что ложных срабатываний
у них быть не должно, и каждая проверена намеренной поломкой того,
что она ловит.

## 6. Проверка, что всё разложено верно

На машине аналитика:

```cmd
dir /b "C:\TI-Console\"
powershell -ExecutionPolicy Bypass -File check-install.ps1
```

Скрипт проверяет разом: редакцию и версию Firefox, наличие
и читаемость файлов, метку «скачано из интернета», целостность
архивов, пути в политике и кодировки AutoConfig.

Дальше — `about:policies` → **Active** (не Errors) и приёмка
из `LOCAL.md`, 37 пунктов.
